Which kinds of attack do AI control tests cover?

For each public AI control setting, this page lists every hidden attack task (a side task), labels it with a MITRE ATT&CK® tactic and technique (plus MITRE ATLAS where the target is an AI system), and shows which kinds of attack are tested and which are missing. A gap is a tactic with zero tasks.

Tested, not caught. A task count shows what is tested, not what is caught. A gap means “untested”, not “dangerous” and not “undefended”.

LinuxArena extras is not included in v0.1, pending permission from its maintainers.

Why this matters

An AI control evaluation reports how often safety measures stop an AI agent that is secretly trying to cause harm. That number only covers the attacks the evaluation includes. If whole kinds of attack are missing, the number says nothing about them. Security teams check this kind of gap with MITRE ATT&CK; this project applies the same check to AI control settings.
